# 前端视觉维护

## 已确认方向

2026-10-15 用户确认 divine/refined 与 workbench 设计稿，并要求落实首页和所有内页，保留动态数学线条及原有功能。正式主题为古典未来主义：黑绿炭色空间、旧金重点、石白文字、雕塑与数学几何。蓝色仅作为原画中的远景，不再作为大面积选中底色。

想法：业务对象之间的关系成为可探索的星图；数学既是视觉语言，也是计算与判断的边界。首页雕塑和缓慢绘制的数学线条构成主视觉，内页把装饰收在标题与图形背景中，保证操作与结果清晰。

## 实现与边界

- `dashboard.html` 使用正式资源与真实导航，保留会话编辑、侧栏入口（含智能分析报告）、原有功能模块和原有进入动画。带功能 hash 的地址可直接进入工作台。
- `sanctum-cover.css/js` 限定首页作用域，移植已认可设计。动态数学使用内嵌 SVG，避免深色浏览器下 object 文档白底；动画可暂停，支持减少动态效果。
- `dashboard-refinements.css` 统一所有模块的导航、表单、表格、状态、结果与移动布局。模块仍通过原有接口和参数运行，不使用设计稿的静态数字作为会话结果。
- `relationship-view.js` 展示后端 ontology/entity_graph 与 catalog/lineage 数据，支持轨道/层级排列、搜索、缩放、键盘选择、节点属性和关系检查；保留完整节点/边列表、断边、自环和双向关系。对象页新增只读加载关系图入口，原注册、查询、执行、审计操作均保留。大图及手机允许在图形容器内滚动。
- `ontology-playground.js` 在模型里增加「本体图」：读取已注册对象、关系、动作和 entity_graph，按列画出对象卡片与基数边。断边只列在图下，不合成节点。登记仍走原有表单。
- 分析结果优先显示服务返回的基期、当期、变化量、变化率，再显示结论、图表和统计明细；SQL/方法证据及完整响应可展开。所有数字来自响应，只做格式化，不在前端重算贡献或检验。
- Vega-Lite / ECharts 的主题仅作用于渲染副本，保留正负语义差异、服务器数据和原有协议。示例图表复用同一渲染器。图表切换会清理实例和观察器；离开页面后的异步结果不打扰新页面。
- 视觉层没有改数据源或图表 Spec 输出协议。算子、证据叙述和 Skill 引用在分析工具变更里同步更新。

### ERP 报告问题可视化（2026-10-16）

解释边界：加法贡献定位变化来源，不证明因果；ANOVA 的产品标志同时要求 p<0.05 和 η²>=0.01，展示层分开解释两者；RFM 频次为明细条数，分群允许重叠；Copilot 异常图只展示返回的 Top 8 洞察中的异常，离群不等于错误。原始叙述保留供核对，其“未拒绝原假设”措辞仍需结合上述产品门槛解释。

验证：ERP 浏览器完整运行，2321 条有效明细；12 个区域×品类单元格与服务返回一致；South 点击显示基期、当期、差额与贡献率；宽/窄布局无页面横向溢出。JavaScript 语法检查通过，pytest 221 passed（21 warnings）。

### 利润深入分析与时间尺度（2026-10-16）

新增 `erp-profit-queries.js` 与 `erp-profit-report.js`：前者生成受控的只读 SQL，由现有 `/tools/sql` 服务算子执行；后者呈现利润桥、因素核查说明、异常订单敏感性、日/周/月/季度/年趋势与成熟方法指南。全部复用 ERP 会话，不新增算子、不改 NLG/图表输出协议、不删除源数据。日期窗口是 ERP 示例的 2024–2025，范围为全部、South、West / Technology。

分解恒等式为 `Π = Q Σ[s(p(1-d)-c)] + R + E`。Q 是总件数，s 是 SKU 件数占比，p 是同品件数加权标价，d 是标价金额加权折扣，c 是单位销售成本，R 是销售额与数量×标价×(1−折扣)的差额，E 是 profit−(sales−cogs)。先对 Q/单位毛利，再对组合/同品毛利，最后对价格/折扣按两期中点展开。固定层级下精确闭合，但不是所有因子排列的 Shapley，也不是因果识别。单期无销售 SKU 用另一期间单位指标补齐，其贡献落在销量/组合；整期无正销量则不解释分解。

金额不一致规则为单行绝对差额 >0.01；敏感性口径排除含该行的整单。订单表始终展示整单金额，分析范围中的变化只计范围内明细。公式残差与排除订单影响不同，不能相加。订单筛查是 ERP 口径一致性检查，不替代一般统计离群检测。

默认种子验证：利润变化 -136537.05；件数 +17303.73、组合 +846.53、折扣 -60739.79、金额不一致 -93947.52，同品标价/单位成本/利润账差约0。排除4笔待核查订单后，变化 -39221.45（-8.1846%）。South 的经营贡献主要为件数/组合负向，West / Technology 的折扣贡献 -49261.17。不同范围的层级中点权重独立计算，因素贡献不能简单跨范围相加。

时间序列补全固定窗口的日历桶，金额无记录补0，非金额比率留空。季度/年度比率重新聚合分子分母，不平均月比率；同比按日历上一年匹配，周同比禁用，避免 ISO 周错配。闰日与边界周需谨慎；无记录不保证数据完整。趋势覆盖全部期间，表格展示最近24期，选择器可查所有期间。

新增测试覆盖单因素方向与金额、SKU进入退出/多因素交互闭合、整单异常敏感性/舍入、三种范围、五种时间粒度、缺少基期。完整测试230通过，21条已有警告。

### 正式通用报告入口（2026-10-16）

REST/MCP 共用 `app/operators/business_report.py`，没有在浏览器计算业务统计。维度图支持累积精确过滤（最多8项），返回全部可重置。字段不齐返回基础报告和未执行原因；利润账式或退货/数量条件不满足时不生成利润桥。SUM 口径限制、空时间桶、部分期间、候选异常等明确说明。

验证包括非ERP中文CSV真实浏览器上传、导入到自动报告导航、折扣单位确认、年度利润分解、区域→商品累积下钻；后端测试涵盖同一计算引擎、字段注入、过滤转义、会话隔离、缺失/非法值、同比与缺字段降级。现有 ERP 会话5张表在服务更新前备份并恢复。

## 正式报告的通用工具集成

报告页直接调用 compare_metric / decompose_change / analyze_sensitivity；共享 metric、time、filters，支持 SUM、比例、去重、窗口内末次余额，时间粒度和时区、完整性水位、无效行策略可选。异常方法支持 MAD/IQR/Z-score，可设置阈值、参考期间、分组及按行/实体排除。默认未知完整性，不自动声明上传数据完整。

图表延用墨绿黑、旧金和灰绿：利润因子与维度使用有符号贡献条，敏感性显示原始变化、排除后变化和差额，并列出样本数量及候选记录。缺失结果显示破折号。单项分解失败不遮蔽成功计算；全部证据可下载。配置改变会提示重新生成，结果同时展示实际运行窗口。去重/余额不做错误的加法分解。
